# M4ML Studio — 실제 배포 제품 PRD 추가 명세

## 제품 정의
사용자가 자신의 Ubuntu/Linux NVIDIA GPU 컴퓨터에서 실행하여 다중 시점 이미지를 불러오거나 기존 COLMAP/Mask 데이터를 재사용하고, 필요시 SAM 3.1로 객체 마스크를 생성·편집하고, 원본 Object-Aware Loss로 학습하여 **색상 Object Mesh**를 볼 수 있는 오프라인 우선 로컬 소프트웨어.

## 프로젝트 시작: 선택 가능한 3개 동선
| 시작 방법 | 필수 데이터 | 검증 | 성공 시 바로 이동 |
|---|---|---|---|
| A: 원본 이미지 | 사진 폴더/파일 | 열기·디코딩·중복·원본 경로 | COLMAP 단계 |
| B: COLMAP 완료 | 실제 등록 카메라와 이미지 + 일관된 sparse 모델 | 등록 이미지/pose/intrinsics/undistortion/파일명·해상도 | SAM 3.1 단계 |
| C: COLMAP+Mask 완료 | B + 등록 이미지별 binary mask | B + mask 존재/대응/크기/색상 의미·값 검증 | Object-Aware 학습 준비 (선택적으로 검토 가능) |

프로젝트 생성 시 세 카드를 통해 한 가지 경로를 선택한다. B/C 경로를 재사용하는 경우 기존 COLMAP/SAM을 **자동 실행하지 않는다**. 잘못된 데이터는 오류를 설명하고 선택적으로 수리하도록 한다. 유효한 데이터 부분만 보존하며 실패를 숨기지 않는다.

### 폴더 및 형식 호환
- 기본 학습 디렉터리 구조는 `<scene>/images/`, `<scene>/mask/`, `<scene>/sparse/0/`이며 mask는 `255=object, 0=background`, 원본 이미지와 일치하는 stem의 PNG.
- 등록된 카메라 포즈는 `<scene>/sparse/0/images.bin|txt`, intrinsics는 `cameras.bin|txt`, 포인트는 `points3D.bin|txt`; 단순 DB 매칭 수만으로 등록 성공이라 판정하지 않는다.
- `images`가 distorted 원본인 경우에는 본래 COLMAP 구조/카메라 모델 확인 후 undistortion **만** 실행할 수 있다. 이미 undistorted라면 중복 undistort 금지. 이미지 변환 때 mask도 동일 좌표계로 옮겨야 하며 이를 검증한다.
- `distorted/`, `input/`, 다른 index (`sparse/1/`), ASCII/binary, 확장자가 다른 이미지·마스크, 폴더명 사용자 지정은 자동 탐지 또는 수동 매핑할 수 있어야 한다.
- 다중 reconstruction component가 있으면 임의로 합치지 않고 사용자가 선택하도록 한다. 등록 안 된 사진은 UI에 남기되 학습에는 미포함.
- 경로 존재, 정상 해독, 중복 ID·파일명, mask shape, 컬러 공간/uint8, black/white 전경 지정, 회전(EXIF), 사진/카메라 대응, 카메라 모델 지원 등을 체크한다. 원본을 건드리지 말고 프로젝트 복사본에서 수리한다.
- `추가 입력 데이터가 필요함`을 구체적으로 표시한다. 부실한 사진이나 프리뷰 이미지만으로 포즈를 꾸며내지 않는다.

## 마스크 편집 상세
- 초기 프롬프트: 클릭할 때마다 결과 자동 추론·갱신. 첫 positive point에서 즉시 요청, negative 추가에도 즉시 갱신. 클릭 순서와 점 라벨의 일관성 유지.
- `다음`, `이전`, `승인하고 다음`, `남은 검토 건너뛰기` 지원. 검토 생략된 자동/가져온 마스크는 `검토 안 함`으로 표기하며, 누락/파손 마스크는 여전히 학습 차단.
- 사용자 브러시 편집은 mask 픽셀에 직접 반영. SAM 재추론이 필요한 상호작용과 수동 편집 모드를 구분. 마지막 반영 중일 때 저장·승인의 일관성을 보장.
- 빠른 연속 클릭 중 첫 결과가 늦게 와도 마지막 요청의 결과만 출력. 실패 시 이전 정상 마스크와 점 목록 유지, 재시도/오류 보기 제공.
- 한 뷰의 수정이 다른 뷰에 확산되는 작업은 대상 프레임과 덮어쓰기 범위를 보여주고 사용자 동의를 받는다.

## 색상 Mesh 결과
- 성공으로 간주하려면 실제 삼각형 Mesh, 정상 vertex/faces 수, 원본 컬러 속성의 보존 여부가 확인돼야 한다. UI 기본보기 `컬러`, 보조보기 `형상`, `와이어프레임`.
- 이름/파일 크기/정점/삼각형 수/색상 포함 여부/학습 iteration/추출 옵션 표기.
- 소스가 유효한 vertex color를 가지는데 화면이 회색이면 제품 결함으로 간주한다. 기존 PLY/GLB 가져오기 시에도 동일 검증.
- 원본 컬러가 없는 경우 ‘색상 없음’으로 표기하고 기하 Mesh는 볼 수 있게 하되 *색상 Mesh 완성*으로 판정하지 않는다.
- 배경은 중립 회색, 조명은 형태를 볼 수 있을 정도로 부드럽게, 컬러를 과도하게 바꾸는 톤매핑 금지; 축/바닥/fit 모델/리셋 카메라 제공.

## 배포 사용자 경험
- 가입/결제/클라우드/로그인 없이 로컬 실행, 가능한 부분 오프라인 사용.
- 첫 실행: 시스템 검사(CPU·RAM·디스크·GPU·드라이버·호환 런타임·COLMAP·SAM weights), 명확한 PASS/WARN/FAIL과 권장 조치. 체크포인트는 외부 유통 권한이 없는 경우 사용자에게 지정/복사 방법 제공.
- 실행 및 프로젝트 데이터는 설치 경로 밖에 저장(XDG 표준: `$XDG_DATA_HOME` / `$XDG_CONFIG_HOME` / `$XDG_CACHE_HOME`, 미설정 시 사용자 홈). 여러 사용자/다른 Ubuntu 머신에서 절대경로 하드코딩 금지.
- 백엔드는 localhost만 바인딩, 임의 경로 접근/파일 삭제 금지, 업로드 검증. 프런트와 워커 종료 시 자식 프로세스 정리. 충돌 후 프로젝트 복구.
- 작업 중 앱을 재시작해도 마지막 **검증 완료 단계**부터 재개 가능. 각 작업 id, 입력 해시, 로그, 단계별 아티팩트 관리.
- 설치 방법은 처음 쓰는 사용자도 복사·붙여넣기 몇 단계로 가능해야 하고, 삭제해도 프로젝트 자료를 기본적으로 보존. 설치 실패 시 진단 로그 내보내기.
