## 2. 발견 결함과 수정

- 작업 PID를 기록하기 직전의 취소가 무시되는 경계 조건을 실제SQLite/지연 시작한 CPU worker로 재현하고, PID와 무관하게 취소 의도를 먼저 저장하도록 수정했다.
- 실제 원본 학습 중 과도한 진행률 DB 쓰기가 SQLite 취소 요청을20초 뒤500으로 실패시켰다. 진행 저장을 최대4Hz로 합치고 원시 로그는 보존했다. 실제 취소200/0.167초,12500회 체크포인트→30000회 재개 성공.
- 취소 대상 PID가 다른 프로세스로 재사용되면 잘못 종료할 수 있었다. 실제 시험용 CPU 자식에서 재현 후 정확한 worker/job 인자와 Linux pidfd로 대상 소유권을 확인한다.
- 같은 경로의 사진·카메라 내용 변경을 기존 재개 검사가 놓쳤다. 실제 등록 사진과 sparse 파일 SHA256을 마스크·설정과 함께 연결한다. 내용 변경은 원본 학습 실행 전에 거부한다. 검증 기록이 없는 예전 중간 저장 지점은 파일을 보존하고 새 학습을 안내한다.
- 새 Ubuntu 설치에서 Qt 시스템 라이브러리 누락을 발견했다. 설치/진단/런처에서 공유 라이브러리를 미리 검사하고 한국어 해결 안내를 표시한다. 기본 실행이 조용히 브라우저로 바뀌지 않는다.
- 가져오기 도중 데이터가 갱신될 때 B/C 두 경로에서 React#310으로 편집기가 사라졌다. 모든 훅 호출 후에 화면을 조건 분기하도록 수정했다. 오류 화면의 대형 로고가 복구 버튼을 밀어내던 문제도 수정했다.
- Qt 종료 시 프로필이 페이지보다 먼저 해제되던 순서를 수정했다. 실제 종료0, 해당 경고 없음 확인.
- 기존 압축본 덮어쓰기와 비결정적 시간/소유자 메타데이터를 제거했다. 명시적 후보 폴더, 원자적·배타적 생성, 고정 epoch 및 정렬된 파일 인벤토리를 사용한다.

## 3. UI/UX

실제 로고와 기존 뷰포트 중심 디자인을 유지했다. 사진/객체 선택/속성/기록/GPU 사용량을 일관되게 표시하고,100회 학습을0k로 표시하던 오류를 수정했다. 실제 메뉴·도움말·단축키·패널 저장·마스크/컬러 모델·밝은/어두운 테마를 검사했다. 내부 탐색 시험이며 정식 초보자 사용성 연구는 아니다.

## 4. 아키텍처

기존 Camera/Segmentation/Training/Export Provider 분리를 유지했다. 대체 segmentation/export 시험 Provider를 레지스트리에 주입하는 계약 시험은 UI/작업 조정기 변경 없이 통과했다. 기본 과학 모델을 교체한 것이 아니다. 재사용 가능한 `studio/artifacts.py`, `studio/progress.py`, 프로세스 소유권 함수와 Qt 의존성 진단을 분리했다. 원본 train.py/render.py/arguments/scene/gaussian_renderer/utils는3221821b 기준 변경 없음.

## 5. Qt 평가

PySide6 6.8.1/Qt WebEngine을 유지한다. 재현된 결함은 앱 구현/시스템 의존성에 있었고 프레임워크 교체의 실증된 우위는 없다. 동일 부하의 Tauri/Electron 비교나 이식 비용의 수치 추정을 만들지 않았다. QML 재작성, Linux WebKit, 별도 Chromium 패키징은 각각 새 회귀·배포 비용을 유발한다.

## 6. 유지보수·확장성

사진/카메라/마스크/설정 변경과 오래된 체크포인트를 구분하고, 확장 Provider 계약과 실제 실패 재현 스크립트를 제공한다. App/API의 큰 모듈과 고정6단계 dispatch는 남은 부채다. 범용 플러그인 시스템을 구현한 것으로 주장하지 않는다.

## 9. 설치·패키징

Ubuntu24.04 시스템 패키지와 Miniforge만 있는 별도 컨테이너의 신규 non-root HOME에 직접 런타임을 생성했다. 개발 HOME/checkout/runtime을 마운트하지 않고 후보·체크포인트·입력 사진만 읽기 전용으로 제공했다. Python3.10/Torch2.5.1+cu118/NumPy1.24.4 및 원본 CUDA 확장을 빌드하고 실제 SAM/학습/추출을 실행했다. Qt 추가 라이브러리는 시험 컨테이너 안에서만 설치했다. 호스트 시스템/드라이버/기존 런타임은 변경하지 않았다. 실제 업데이트 전후 기존 프로젝트342개 파일과 Python2개 파일은 동일했다. 시험 컨테이너의 CUDA 확장2개는 명시적 재빌드로 해시가 달라졌으며, seed42/64Gaussians 원본 CUDA forward/backward·polarization·optimizer 수치가 기존 기준과 정확히 일치했다. 런타임 전체 바이트 동일 주장은 하지 않는다.

기존0.3/0.4/0.5 압축본을 덮어쓰지 않는다. `scripts/package_release.py --internal-research --output-dir <새 폴더>`로 후보를 만든다. 전체 번들2개가 바이트 동일함을 확인했다(재현 후보70613bb5ce282efcef0935b54e0eba98ed8edcd07374474c62abc8ba9fd55870). 이는 소스+고정 바이너리+정적 UI 번들의 재현성이고 pip/CUDA 런타임 전체의 bit-for-bit 재현성 주장은 아니다. 최종 후보 및 후속 설치 검사는 번들 옆 기록에 연결한다.
